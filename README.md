# Internship ideas

In February you will need a new project. This is where we work out what it should be.

Below are some ideas to start with. Some are from Smári and some are from Claude (the AI assistant Smári works with). None of them are decided, and the best project may well be one that isn't on the list yet. **We would really like yours.**

You have worked inside the website for a while now, so you know things about it that we don't: what is awkward, what is missing, what you wished existed when you started. That is exactly the kind of knowledge good projects come from.

## How to add an idea

Everyone pushes straight to `main`. No branches, no pull requests, no approval.

```bash
git clone https://github.com/ellertsmari/Internship-ideas.git
cd Internship-ideas
```

Open `README.md`, add your idea at the bottom of the list, then:

```bash
git add README.md
git commit -m "Add idea: <your idea>"
git pull --rebase
git push
```

You can also edit the file directly on GitHub with the pencil icon, which is fine too.

A few things that make this easier:

- **Half an idea is enough.** One sentence is a perfectly good start. Someone else may have the other half.
- **Nothing is too big, too small or too strange.** We can always shrink a big idea or grow a small one.
- **Build on other people's ideas.** Add a comment, a question, a "+1" or a variation under any idea, including Smári's and Claude's. Disagreeing is welcome.
- **It doesn't have to be code.** Research, design, user testing and content are all real projects.
- **Put your name on it**, so we know who to ask about it.

If an idea needs more room (sketches, links, screenshots), add a file or a folder for it and link to it from here.

A template you can copy:

```markdown
### Title of the idea
*From: your name*

What it is, and why it would be good. Who is it for?

**Comments**
- 
```

## The ideas so far

### 1. A friendlier calendar
*From: Smári*

Develop the calendar so it is more pleasant and obvious to use. Google Calendar is a good source of inspiration: how you move between day, week and month, how you create and move an event, how much you can see at a glance.

### 2. Better group projects, with peer evaluation
*From: Smári*

Make the group project part of the site nicer and easier to work with. One example: a peer evaluation process like the one Sustainable Island has now, where group members give each other feedback as part of the project.

**Comments**

### 3. A theme for every module
*From: Smári*

Give each module its own visual theme, and have the site switch to it automatically when the module starts, based on the calendar. The site would look different in a design module than in a back-end module.

**Comments**
- 

### 4. How does the school get more students?
*From: Smári*

A research project. What could the school do to reach more people? Some directions to look at:

- SEO: being found on search engines
- GEO: being found and recommended by AI assistants
- Changing direction: towards AI-driven web development, Forward Deployed Engineer, or something similar

The result could be a report with recommendations, and possibly the first changes to the site.

**Comments**
- 

### 5. An app with push notifications
*From: Smári*

Turn the website into an app that can send push notifications, so that students notice what is happening in the calendar instead of having to remember to look.

**Comments**
- 

### 6. Gamification: the student just ahead of you
*From: Smári*

Let students see how they are doing compared to others: who has returned more guides, done more reviews, or has a better average grade. This could also be one point system built from all three.

The important part: each student only sees **the one student just above them and the one just below them**, never the full list. That makes you want to pass the person ahead of you, or stay ahead of the person behind you, without anyone feeling bad about someone who is far beyond them.

**Comments**
- 

### 7. A showcase of student work
*From: Claude*

A public gallery of the best things students have built, chosen by the students or the teachers. Students get something to be proud of and to show an employer. People thinking about applying get to see what you can actually make after a year here, which is more convincing than any description of the programme. This connects well with idea 4.

**Comments**
- 

### 8. "What should I do today?"
*From: Claude*

One screen that answers that question for a student: the guide that is due next, the reviews waiting for you, the feedback you haven't read, what is on the calendar today. Right now that information lives in several places. This is mostly a design and user research project: finding out what students actually look for when they open the site.

**Comments**
- 

### 9. Make giving and getting feedback better
*From: Claude*

Students review each other's work, and a good review is one of the most valuable things on the site. What would help someone write a better one? Prompts while you write, examples of a great review, a way for the receiver to say "this helped me"? And on the other side: how do we make sure feedback is actually read and used?

**Comments**
- 

### 10. Test the site with real students, then fix what you find
*From: Claude*

Sit down with a few students, watch them use the site on their own phone and laptop, and write down everywhere they get stuck. Include accessibility: can you use everything with only a keyboard, or with a screen reader? Then fix the top problems. A project like this often finds things nobody on the team has noticed, and it gives you a clear before and after to show.
